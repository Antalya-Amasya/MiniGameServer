# 面试时可以怎么讲

这些是这个仓库里的取舍，不是通用标准答案。

## 为什么用 epoll

阻塞 `read` 配每连接一个线程时，线程数等于连接数。epoll 让一个线程等很多 fd。井字棋的包很小，网络本身不是 CPU 大头，但线程数量和生命周期会先变成问题。

## 为什么用 LT，不用 ET

水平触发下，缓冲区里还有数据时 epoll 会继续通知。边缘触发少一次通知就要自己把缓冲区读空，漏一次就会卡住。这个服务器的包很短，LT 更不容易写错。没有测量证明 ET 是瓶颈，所以没有改。

## 为什么只有 Reactor 碰 socket

`OutputBuffer` 和 `epoll_ctl` 都假定只有一个线程写 fd。Worker 如果直接 `send`，会和 `EPOLLOUT` 的 flush 抢同一块缓冲。Worker 只产生字符串。

## 为什么还要线程池

登录要做 bcrypt，历史查询要等 MySQL。这两件事如果留在 Reactor 里，所有连接的 `epoll_wait` 都会停。线程池把慢操作挪走。数量夹在 2 到 4，因为业务步骤很短，更多线程不会让井字棋变快。

## 为什么要 SessionLane

线程池会并行。同一个客户端的 `MOVE 0 0` 和后面的命令不能两个 worker 同时改这一局。每条连接一个队列，队列里一次只跑一个任务。不同连接可以并行。

## 为什么不能用 fd 当异步身份

fd 关闭后会被下一次 `accept` 复用。Worker 完成时如果还按 fd 写，就会写到新连接上。所以回包带 connection id，Reactor 对不上就丢弃。

## 为什么用 eventfd 和 timerfd

Worker 需要叫醒阻塞在 `epoll_wait` 里的 Reactor，这是 `eventfd`。空闲超时如果靠每个连接一个定时器线程，又回到线程泛滥。一个 `timerfd` 放进 epoll，周期是空闲时间的一半，限制在 100 毫秒到 1 秒。

## shared_ptr 和 weak_ptr

任务比连接活得短或长都不固定。`shared_ptr<Session>` 保证任务还在跑时对象不被析构。房间只存 `weak_ptr`，玩家断开后房间不会把连接留住。这里没有把它们换成裸指针，因为测量没有证明引用计数是热点，而生命周期错误比少一次原子操作严重。

## TCP 半包和粘包

一次 `recv` 可能只有半行，也可能有两行。`LineBuffer` 按 `\n` 切。超过 1024 字节还没有换行，就认为这行非法并关连接。

## 为什么要 output buffer

`send` 可以只写出一部分。没写完的字节留在 `OutputBuffer`，连接改成关注 `EPOLLOUT`，下次再写。上限 256 KiB，防止对端不读时内存一直涨。

## 背压

三层都有上限：线程池 1024、每连接命令 32、输出 256 KiB。满了就拒绝或关连接，而不是继续排队。

## 数据库为什么不在 Reactor 上

一次查询要等 Windows 上的 MySQL 往返。放在 worker 上，Reactor 还能 accept 和转发别的连接。房间锁也不包住 SQL，避免一个慢查询挡住所有房间。

## 连接池、预处理语句、bcrypt

池是 4 条长连接，避免每条命令都握手。SQL 参数用绑定，不把用户名拼进语句。口令只存 bcrypt `$2b$`，cost 12。登录慢主要就是这个 cost，Phase 5 的延迟曲线和它一致，所以没有为了压测把 cost 降下来。

借出连接时 `mysql_ping`。失败最多重建 3 次。这是故障恢复，不是性能优化，它会多一次往返。

## 关闭顺序

先停止接收，再排空 worker，再关 fd，最后关数据库池。反过来的话，worker 还可能去用已经关掉的连接。

## fd 泄漏怎么看

记录 `/proc/<pid>/fd` 的数量。1000 次连接并关闭之后，数量回到压力前的基线，才算没有把 fd 留在进程里。

## ASan 和 Valgrind

ASan 在独立的 sanitizer 构建里看越界和部分泄漏，速度快，适合每次回归。Valgrind 跑普通 Debug 构建，能看 definite leak 的调用栈，更慢。两者不要同时开。

## perf 看什么

如果大部分时间在 `epoll_wait`，说明服务器在等 I/O，不是自己的循环写坏了。如果 bcrypt 或 MySQL 客户端占主要 CPU，那是认证和查询的成本。只有自有代码出现明显、可重复的热点，才值得改数据结构。这台 WSL 上没有可用的 `perf`。
